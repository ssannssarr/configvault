# ConfigVault

Snapshot-based dotfiles backup for Arch Linux, with two deliberately separate
Git layers:

1. **Source** — the real `~/.config`. ConfigVault never reorganizes it.
2. **Private backup** — a local Git repository containing complete snapshots,
   optionally pushed to a private GitHub repository.
3. **Public dotfiles** — a separate Git repository containing only paths
   explicitly selected in `~/.config/.gitinclude`.

> ## Security warning
>
> A private GitHub repository is **access-controlled storage, not encrypted
> storage**. Anyone with access to the repository, the GitHub account, or a
> leaked token can read every snapshot. ConfigVault does not encrypt backups.
>
> ConfigVault also excludes a conservative list of known credential stores and
> private-key material by default. That list is a safety net, not a guarantee.
> Review your own configuration before pushing it anywhere.

## Requirements

- Arch Linux (other Linux distributions should work)
- Python 3.12+
- Git
- `uv`
- systemd user session (only for the timer)

`rsync` is not required; copying uses Python filesystem APIs.

## Install

From this checkout:

```bash
uv sync
uv run configvault --help
```

For a persistent command:

```bash
uv tool install .
configvault --help
```

The systemd unit generated by `configvault init --install-units` records the
resolved executable path, so a `uv tool` install or a virtualenv install both
work.

## Quick start

Create **two empty GitHub repositories** first. SSH remotes are recommended;
do not put tokens in remote URLs.

```bash
configvault init \
  --private-remote git@github.com:YOURNAME/dotfiles-private.git \
  --public-remote  git@github.com:YOURNAME/dotfiles.git

# Review the generated manifest before publishing anything.
$EDITOR ~/.config/.gitinclude

configvault snapshot
```

`init` creates the configuration, both Git repositories, and a commented
`.gitinclude` template. It does **not** create a snapshot and does **not**
enable the timer.

The first snapshot copies the complete source tree. With a large `~/.config`
(browser profiles can be several gigabytes), expect the first run to take a
while. ConfigVault does not silently exclude browser caches; use the
`snapshot.exclude` configuration if you want a smaller backup.

## Layout

```text
~/.config/configvault.toml          configuration
~/.config/.gitinclude               public selection manifest

~/.local/share/configvault/
├── repo/
│   ├── .git/
│   ├── snapshot/                   complete private snapshot
│   └── metadata.json               modes, mtimes, hashes, symlink targets
├── public/                         public Git working tree (default)
│   └── .git/
├── logs/
│   └── configvault.log
└── state/
    ├── lock                        mutating-operation lock
    ├── last-snapshot.json
    └── public-manifest.json        exactly which public files are managed
```

Paths are configurable. The data directory must not be inside the source
directory, and the public repository must not be inside the source directory.

## Configuration

`~/.config/configvault.toml`:

```toml
source = "/home/you/.config"
data_dir = "/home/you/.local/share/configvault"
public_dir = "/home/you/.local/share/configvault/public"
public_manifest = "/home/you/.config/.gitinclude"

private_remote = "git@github.com:you/dotfiles-private.git"
public_remote = "git@github.com:you/dotfiles.git"
branch = "main"

[snapshot]
exclude = [
  "**/.git",
  "**/.git/**",
  ".git-credentials",
  "**/.git-credentials",
  "git/credentials",
  "gh/hosts.yml",
  "gcloud",
  "gcloud/**",
  "keyrings",
  "keyrings/**",
  "**/id_rsa",
  "**/id_rsa.*",
  "**/id_dsa",
  "**/id_dsa.*",
  "**/id_ecdsa",
  "**/id_ecdsa.*",
  "**/id_ed25519",
  "**/id_ed25519.*",
  "**/*.pem",
  "**/*.key",
  "**/*.p12",
  "**/*.pfx",
  "**/*.kdbx",
  "**/.env",
  "**/.env.*",
  "**/credentials.json",
  "**/token.json",
]
```

- `snapshot.exclude` **replaces** the default list. Remove entries only if you
  understand the exposure.
- `.git` directories are excluded from private snapshots. A nested repository's
  working files are still snapshotted; its Git metadata is not.
- `private_remote` and `public_remote` may be empty/omitted to work entirely
  locally.
- `branch` is used for both repositories.
- The config file is itself inside `~/.config` by default, so it is included in
  private snapshots. Public export hard-denies `configvault.toml` and
  `.gitinclude`.

## Snapshot semantics

`configvault snapshot`:

1. Acquires the state lock.
2. Repairs any interrupted previous snapshot.
3. Copies the live source into a staging directory under `repo/.git/`.
4. Preserves symlinks as symlinks (never follows them), regular files,
   directory/file modes, and mtimes.
5. Hashes every regular file and compares the result with the previous
   snapshot metadata.
6. Atomically swaps the staged tree into `repo/snapshot/`.
7. Writes and commits `repo/metadata.json` plus the snapshot.
8. Keeps the previous snapshot directory until the commit succeeds.
9. Synchronizes the private repository.
10. Exports and pushes the public selection.

Behavior details:

- **Mirror deletion.** A file removed from `~/.config` is removed from the
  latest snapshot. It remains recoverable from private Git history.
- **No change, no commit.** If nothing changed, no commit is created.
- **Custom messages.** `configvault snapshot -m "Before Niri changes"`.
- **Empty source.** The first empty snapshot creates a commit; later empty
  snapshots are no-ops.
- **Interrupted operations.** Staging and the old snapshot are kept under
  `repo/.git/configvault/`. The next snapshot repairs the swap or rolls back to
  `HEAD`. The previous successful snapshot is never intentionally destroyed.
- **Special files.** Sockets, FIFOs, and device nodes are skipped with a
  warning.
- **Hardlinks, ACLs, xattrs, and ownership** are not preserved. Modes, mtimes,
  content, and symlink targets are.
- **Git metadata limitation.** Git itself records only the executable bit.
  ConfigVault's committed `metadata.json` is what allows private restore to
  recover full modes, mtimes, and empty directories.

### Metadata file

`repo/metadata.json` is committed with every snapshot and contains:

- root and per-entry modes and mtimes
- file sizes and SHA-256 hashes
- symlink targets
- entry kinds

It contains no file contents.

## Private synchronization

After a successful snapshot, ConfigVault pushes the private repository. The
sync algorithm:

1. Fetches the remote branch.
2. If the remote does not exist, pushes a new branch.
3. If local and remote are equal, reports up to date.
4. If the remote is an ancestor of local, pushes normally.
5. If local is an ancestor of remote, refuses: the remote has commits not
   present locally.
6. If histories diverge, refuses: no force-push, no automatic merge.

If the network is unavailable, the local commit remains intact and the failure
is reported. `configvault sync` retries later. ConfigVault never discards local
commits and never force-pushes.

## Public export

### `.gitinclude` syntax

Patterns are relative to the source root and use `/` separators.

| Syntax | Meaning |
|---|---|
| `niri/**` | everything beneath `niri` |
| `niri/*` | immediate children of `niri`; a matched directory includes its subtree |
| `**/*.conf` | `.conf` files at any depth |
| `zsh/?rc` | `?` is one non-`/` character |
| `foo/` | shorthand for `foo/**` |
| `!nvim/**/secrets/**` | exclusion; exclusions always win |
| `# comment` | full-line comment |

Additional rules:

- A pattern that matches a directory selects the whole subtree beneath it.
- Patterns are root-relative. A bare `name` matches only the root `name`, not
  `a/name`. Use `**/name` for any depth.
- Blank lines and full-line comments are ignored.
- Not supported: brace expansion, character classes, inline comments, and
  `.gitignore` semantics. `**` must be a complete path segment.
- A manifest with no inclusion patterns is refused unless
  `--allow-empty` is passed explicitly.

Example:

```gitignore
niri/**
nvim/**
alacritty/**
fuzzel/**
zsh/**

!nvim/**/secrets/**
```

### Export behavior

- Only selected regular files and symlinks are published.
- Exclusions override inclusions.
- Deletions are mirrored: if a previously managed file disappears from the
  selection, it is removed from the public repository.
- ConfigVault records every managed public path in
  `state/public-manifest.json`.
- Only managed paths are staged in Git. If the public repository has staged
  changes outside that set, export refuses and asks you to commit or unstage
  them.
- A file that exists in the public repository but is not recorded as managed is
  never overwritten or deleted. Export refuses with a collision error.
- A managed file replaced by a manually maintained directory is protected.
- An empty selection is refused unless `--allow-empty` is given.
- Secret-like paths (credential filenames, private-key extensions, `.env`,
  secret/token names, keyring/gcloud directories) are refused unless
  `--allow-suspicious` is given. This is a heuristic.
- `configvault.toml`, `.gitinclude`, and anything under `.git` are always
  refused as public export targets.
- Public export is independent of private Git history. It reads the live source
  and can run without a private snapshot.
- After export, ConfigVault commits and pushes the public repository. A push
  failure preserves the local public commit and is reported; it does not roll
  back the export.
- Symlinks are preserved. Modes and mtimes are set in the public working tree,
  but Git clones only preserve the executable bit; public clones do not retain
  full modes or mtimes. Empty directories are not tracked by Git and are not
  published.

The public repository never receives the private snapshot or its metadata.

## Restore

```bash
configvault restore <commit>
configvault restore <commit> --yes   # non-interactive
```

Restore is deliberately staged and reversible:

1. Validate the commit exists and is a ConfigVault snapshot commit.
2. Create a safety snapshot of the current live configuration.
3. Materialize the selected snapshot into a staging directory next to
   `~/.config`.
4. Recreate empty directories from metadata and validate every path, kind,
   hash, symlink target, mode, and mtime.
5. Rename the live configuration to a temporary backup and rename staging into
   place.
6. On failure, put the backup back.
7. Remove the temporary backup only after the swap succeeds.

Restore does not create a new snapshot of the restored state. The safety
snapshot is the newest private commit; `configvault status` will show the
difference between the restored live tree and that safety commit. Run
`configvault snapshot` to record the restored state.

## systemd automation

The timer is:

```ini
[Timer]
OnCalendar=*-*-* 03:00:00
Persistent=true
RandomizedDelaySec=15m
Unit=configvault.service

[Install]
WantedBy=timers.target
```

The service is `Type=oneshot`; there is no daemon. Install the units:

```bash
configvault init --install-units
systemctl --user daemon-reload
systemctl --user enable --now configvault.timer
```

`init` installs units but does not enable them. Manual execution is always
available with `configvault snapshot`.

## CLI

| Command | Purpose |
|---|---|
| `configvault init` | Create configuration, repositories, and manifest template |
| `configvault snapshot [-m MSG]` | Snapshot, then sync and export |
| `configvault status` | Pending changes, HEAD, remote tracking, public state |
| `configvault history [-n N]` | Snapshot history |
| `configvault diff [COMMIT] [--patch]` | Changes between snapshots |
| `configvault sync` | Push existing private commits |
| `configvault export [--dry-run]` | Export selected public dotfiles |
| `configvault restore COMMIT [--yes]` | Restore a snapshot safely |
| `configvault config` | Show paths and settings |
| `configvault version` | Print version |

Useful flags:

```bash
configvault snapshot --no-sync --no-export
configvault export --dry-run
configvault export --allow-empty
configvault export --allow-suspicious
configvault export --no-push
```

Snapshot sync/export failures are reported as warnings; the local private
snapshot is still considered successful. Use `configvault sync` or
`configvault export` to retry.

## State, logs, and recovery

- `state/lock` prevents two mutating operations from running at once.
- `state/last-snapshot.json` records the last local snapshot result.
- `state/public-manifest.json` is the authoritative list of public files
  ConfigVault manages. If it is lost, export refuses to overwrite existing
  files rather than guessing.
- `logs/configvault.log` is an append-only operation log. Logging failures never
  fail a backup.
- Interrupted snapshot staging/old directories are repaired automatically on the
  next snapshot.

## Testing

```bash
uv run pytest
```

The suite uses temporary directories and disposable bare Git repositories. It
never touches the real `~/.config` by default. Coverage includes:

- initial, modified, new, deleted, and empty snapshots
- symlinks, modes, mtimes, nested `.git` exclusion
- interrupted copy and failed commit rollback
- crash recovery after a swap
- private push, offline failure, remote-ahead, and divergence refusal
- public include/exclude rules, deletion mirroring, manual-file protection,
  missing-state protection, staged-change refusal, empty/suspicious approvals,
  tool-metadata refusal, symlinks, modes, and public push failure
- restore success, safety snapshots, empty directories, invalid commits,
  staging failure, swap failure rollback, and non-snapshot commits
- systemd unit schedule and installation
- CLI end-to-end workflow across both Git layers

## Limitations

- **No encryption.** Private GitHub repositories are not encrypted storage.
- **Secret detection is heuristic.** The default exclude list and public
  suspicious-path checks reduce accidents; they cannot prove a file is safe.
- **No automatic pull/merge.** Divergent remote histories require manual
  integration.
- **Full snapshots.** Every snapshot stores a complete tree in Git. Git
  deduplicates unchanged blobs, but the first snapshot can be large.
- **Git metadata limitations.** Private restores recover full modes/mtimes via
  `metadata.json`; public clones only preserve the executable bit. Empty
  directories are not represented in public Git.
- **No hardlink/ACL/xattr/ownership preservation.**
- **Restore replaces the whole source directory.** Close applications that may
  write into `~/.config` during a restore.
- **No daemon and no background watcher.**
